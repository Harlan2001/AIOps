# 训练数据标准化规范（含真实示例）

> 本文说明两件事：**第一章讲清我们需要对方交付什么、什么格式；其余章节回答标准化的训练数据长什么样、怎么填。**
> 文中所有示例均取自仓库内的真实运行记录（`reports/llm_demo_result.txt` 真实诊断输出、`汇报演示文档.md`），规则描述与代码实现（`engine/parser.py`、`ml/dataset.py`）逐条对齐，可对照核验。

---

## 一、我们需要什么交付物

**交付物：一批 TLOG 报错记录（FATAL/ERROR 级日志，即 LLEVEL 为 20 或 30 的记录），用于扩充训练数据。** 每条报错一行，交付格式二选一：

### 方式 A：原始导出（推荐，门槛最低）

CSV / Excel / 日志导出文本均可，提供以下 TLOG 原始字段（字段名与库表 `ULOG.TLOG` 一致，与标准字段的对应关系如下；除 `LTEXTE` 外缺失列可留空）：

| TLOG 字段 | 对应标准字段 | 说明 |
|-----------|-------------|------|
| `LTEXTE` | `text` | **报错原文，唯一必需**，原样不改字 |
| `LDATE` | `ldate` | 日志时间，`YYYY-MM-DD HH:MM:SS` |
| `LLEVEL` | `llevel` | 日志级别：20=FATAL，30=ERROR |
| `ERRCODE` | `errcode` | 业务错误码，无则为 0 |
| `ID` | `id` | 日志流水号，便于回溯 |
| `FUNC_NO` | `func_no` | 功能号 |
| `LSECTION` | `lsection` | 调用栈原文，用于解析报错位置（代码包.过程:行号） |

选择方式 A 时，归一化与打标（`skeleton`/`cls`/`biz_type`）由我们按本规范完成，你方无需处理。

### 方式 B：标准化 CSV

直接按第六章的模板与自查清单交付 `dataset.csv` 同结构文件：UTF-8 编码、含表头、固定 12 字段及顺序，交付前逐项核对自查清单。

### 通用要求（两种方式都适用）

- 一条报错一行，UTF-8 编码（Excel 请另存为"CSV UTF-8"格式）；
- 字段内容本身含逗号时，用双引号将该字段整体包裹；
- **报错原文必须原样保留**——错别字、多余空格也不要改，这直接影响骨架归一化的正确性。

## 二、标准化的训练数据长什么样

一句话：**一条标准化训练数据 = `data/ml/dataset.csv` 里的一行，固定 12 个字段**，由 `ml/dataset.py` 从 Oracle 库 `ULOG.TLOG`（`LLEVEL IN (20,30)`，即 FATAL 与 ERROR 级日志）生成（字段定义见 `ml/dataset.py:22-23`）。手工补充数据时，把报错文本整理成同样结构的一行即可。

下面是一条**真实**训练数据（日志 ID 3674173785，诊断报告见 `reports/llm_demo_result.txt` L3-L45）：

```
3674173785,2026-05-28 20:07:51,30,150302029,,biz,[期权合约=>?]结算价不存在,[期权合约=>?]结算价不存在,PKC_M_SHFE_OPTION,SP_CLOSE_CHECK_MAIN,[期权合约=>au2606C456]结算价不存在,
```

逐字段拆解（"出处"指该值在真实诊断报告中的位置）：

| 序 | 字段 | 本例的值 | 含义与出处 |
|---|------|---------|-----------|
| 1 | `id` | `3674173785` | 报错流水号（报告 L5"日志ID"） |
| 2 | `ldate` | `2026-05-28 20:07:51` | 日志时间，格式 `YYYY-MM-DD HH:MM:SS`（报告 L10"报错时间"） |
| 3 | `llevel` | `30` | 日志级别：20=FATAL，30=ERROR（取自原始日志；演示报告未展示，以实际日志为准） |
| 4 | `errcode` | `150302029` | 业务错误码，无则填 0（报告 L11"错误码"） |
| 5 | `func_no` | （留空） | 功能号，无则留空 |
| 6 | `cls` | `biz` | 一级分流标签（报告 L15"路由=biz"），规则见第四章 |
| 7 | `biz_type` | `[期权合约=>?]结算价不存在` | 二级类型标签（报告 L16"业务类型"），规则见第四章 |
| 8 | `skeleton` | `[期权合约=>?]结算价不存在` | 归一化骨架（报告 L19/L23 召回骨架），规则见第三章 |
| 9 | `module` | `PKC_M_SHFE_OPTION` | 代码包名，自调用栈解析（报告 L12"报错位置 PKC_M_SHFE_OPTION.SP_CLOSE_CHECK_MAIN:339"，解析逻辑见 `engine/parser.py:61-81`） |
| 10 | `deep_proc` | `SP_CLOSE_CHECK_MAIN` | 过程名，同上解析 |
| 11 | `text` | `[期权合约=>au2606C456]结算价不存在` | 报错原文，**原样保留、不改一个字**（报告 L13） |
| 12 | `lsection` | （留空） | 调用栈原文，无则留空（报错位置即由它解析而来） |

**必填 4 项**：`text`、`skeleton`、`cls`、`ldate`。其余有则填、无则留空（`errcode` 无值填 0）。若某字段内容本身含逗号（如持仓不足类骨架），须用双引号将该字段整体包裹。

## 三、骨架（skeleton）怎么填：归一化三条规则

同一种报错每次出现时具体数值不同，但结构相同。把可变部分替换为占位符后得到的模板即骨架，**同一骨架 = 同一类报错**。归一化按顺序执行三步（实现见 `engine/parser.py:38-45`）：

1. **参数值占位为 `?`**：`[字段=>值]` 或 `[字段->值]` 保留字段名与分隔符，值替换为 `?`；
2. **数字替换为 `#`**：日期、编号、数量、行号等数字串替换为 `#`（字母数字混合时只换数字，如 `au2606` → `au#`）；
3. **压缩空白并截断**：连续空白压缩为一个、去首尾空格、截断至 120 字符。

注意顺序：**先替换参数值，再替换数字**——参数值里的数字已随值一起变成 `?`，不会再变成 `#`。

### 正确示例（全部来自真实数据，出处见第五章）

| 报错原文 | 归一化骨架 |
|---------|-----------|
| `[期权合约=>au2606C456]结算价不存在` | `[期权合约=>?]结算价不存在` |
| `平仓错误,[会员->016811][客户->0000000168][交易员->trader][成交编号->20260611020000025653][合约->mAu(T+D)][买]持仓不足,尚缺<2>` | `平仓错误,[会员->?][客户->?][交易员->?][成交编号->?][合约->?][买]持仓不足,尚缺<#>` |
| `修改[合约=>au2607C376]失败` | `修改[合约=>?]失败` |
| `[用户=>yuew]使用未注册[IP地址=>10.253.60.84]` | `[用户=>?]使用未注册[IP地址=>?]` |
| `用户名或密码错误` | `用户名或密码错误`（无参数无数字，骨架=原文） |

要点：**可变部分（参数值、数字）替换为 `?` / `#`，不变部分（字段名、中文、标点）原样保留**；`?` / `#` 均为原位替换，两侧不加空格。

### 一个真实的边界情况

原文中一个方括号内可能用 `、` 塞多个键值对：

```
原文：[交易员=>trader1、会员号=>016815、客户号=>0000002044]可用库存量不足，不允许分配
骨架：[交易员=>?]可用库存量不足，不允许分配
```

整个括号按一个参数处理，塌缩为"第一个字段名 + `=>?`"（真实行为，见 `reports/llm_demo_result.txt` L153/L158）。遇到这种文本照此填写，不要拆成三个 `?`。

### 错误示例（规则演示）

| 错误骨架 | 问题 |
|---------|------|
| `[合约=>au2606C456]结算价不存在` | 未将值 `au2606C456` 替换为 `?`，同骨架不同取值会被误判为不同类 |
| `[合约=>au#C#]结算价不存在` | 顺序颠倒：先换了数字导致参数匹配不上，正确结果应为 `[合约=>?]结算价不存在` |
| `到期日 # 为非交易日` | `#` 两侧不应加空格，须原位替换为 `到期日#为非交易日` |

## 四、标签怎么填

### 一级标签 `cls`（四选一）

判定按以下顺序，命中即停（实现见 `engine/parser.py:84-97`，词表见 `engine/parser.py:23-26`）：

| 顺序 | 标签 | 判定条件 | 真实示例 |
|-----|------|---------|---------|
| 1 | `ora` | 含 `ORA-` 或 `SQLCODE` | Oracle 技术错误，本期不诊断 |
| 2 | `other` | 不含中文 | 兜底 |
| 3 | `biz` | 含业务报错词（不存在/失败/异常/错误/不允许/不可/不足/不能/冲突/超时/重复/非法/无法/请检查/未/没有/不一致/不匹配 等），**或** errcode 非零 | 本文第五章全部业务报错 |
| 4 | `noise` | 含噪音词（成功/完成/启动/恢复/无需要发送/已处理/已恢复） | `无需要发送的DAMS数据！` → noise（`汇报演示文档.md` L146-168，路由=noise 置信度 1.000；噪音词表见 `rules/noise_rules.yaml`） |
| 5 | `other` | 以上皆非 | 兜底 |

注意顺序意味着：**同时含噪音词和报错词的（如"清算未完成"）判 biz 不判 noise**。

### 二级标签 `biz_type`（仅 cls=biz 时填写，其余留空）

取该报错的骨架文本本身；骨架频次未进 Top-30 的统一填 `other_biz`（交由大模型处理，实现见 `ml/dataset.py:21,72-75`）。真实对照：

- `[期权合约=>?]结算价不存在` 高频进入 Top-30 → `biz_type=[期权合约=>?]结算价不存在`（报告 L16）；
- `[交易员=>?]可用库存量不足，不允许分配` 未进 Top-30 → `biz_type=other_biz`（报告 L156）。

## 六、手工补充数据：模板与自查

可复制以下两行（表头 + 模板行），按占位说明替换（字段顺序固定，与 `ml/dataset.py:22-23` 一致）：

```
id,ldate,llevel,errcode,func_no,cls,biz_type,skeleton,module,deep_proc,text,lsection
〈流水号〉,〈YYYY-MM-DD HH:MM:SS〉,30,〈错误码，无填0〉,〈功能号〉,〈noise/ora/biz/other〉,〈biz填骨架或other_biz，非biz留空〉,〈归一化骨架〉,〈代码包名〉,〈过程名〉,〈报错原文不改字〉,〈调用栈〉
```

填完后对照第五章示例自查六项：

- [ ] `text` 为报错原文，未改任何字
- [ ] `skeleton` 已按第三章归一化：参数值为 `?`、数字为 `#`、原位替换无多余空格
- [ ] 同一类报错的 `skeleton` 完全一致（可对照已有骨架表）
- [ ] `cls` 仅取 `noise`/`ora`/`biz`/`other` 之一；非 biz 的 `biz_type` 留空
- [ ] biz 的 `biz_type` 填骨架文本或 `other_biz`
- [ ] `ldate` 格式为 `YYYY-MM-DD HH:MM:SS`；含逗号的字段已用双引号包裹

> 说明：仓库中暂无离线格式校验脚本。`scripts/verify_samples.py` 的用途是**连库验证 runbook 候选 SQL**（用真实报错样本试跑诊断 SQL），不校验 CSV 格式，请勿混淆。

## 七、背景与衔接（简要）

- **数据层与规则层**：本规范管的是数据层（`var/data/ml/dataset.csv` 训练数据）。另有规则层负责自动诊断——`src/ai_ops/assets/rules/errors.yaml` 当前登记 3 个报错类型（结算价不存在 / 递延费率不存在 / 平仓时持仓不足），各配一套诊断方案（`src/ai_ops/assets/rules/runbooks/rb_*.yaml`，发布期可用 `AIOPS_RULES_DIR` 外挂覆盖）。规则未覆盖的报错由大模型兜底。
- **数据怎么来**：连库环境下跑 `uv run python scripts/gen_rule_seed.py`（生成报错骨架种子到 `var/data/`）与 `uv run python -m ai_ops.ml.dataset`（生成训练集）；种子规模、类型数量等以实际生成结果为准。
- **新增诊断规则**：高频报错可在 `errors.yaml` 登记关键词并仿照现有 runbook 编写诊断步骤（参照 `rb_settle_price.yaml`），使其具备自动诊断能力。
- **诊断报告长什么样**：批量演示报告由 `uv run python scripts/llm_demo_batch.py` 生成到 `var/reports/llm_demo_result.txt`，另见 `汇报演示文档.md` 的真实输出，本文不再重复。

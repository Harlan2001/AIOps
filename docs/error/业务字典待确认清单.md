# DIMPLE AIOps runbook 业务字典待确认清单

> 背景：runbook 表名/列名已对照 `GaussDB_dimple_全量表结构与字段含义清单.md`（977 张表）全部核验一致，
> 但以下 4 项依赖**字典码值**的语义，需 DIMPLE 业务/数管/结算系统负责人确认后才能去掉代码注释中的"待确认"标注。
> 在确认前，相关 runbook 的 SQL 照常执行，但**阈值的具体含义**以注释口径为准，诊断结论可能偏保守。

## 1. tc_real_money.invest_id 与报错文本"客户号"的映射

| 项 | 内容 |
| --- | --- |
| 涉及 | `rb_fund_short.yaml` → step `account_money` |
| SQL | `SELECT invest_id, last_remain, used_money, using_money, out_money FROM dimple.tc_real_money WHERE invest_id = :client` |
| 现状 | 报错文本中的"客户"被 param_alias 映射为 `:client`，直接拿来等值匹配 `invest_id`（varchar14 投资者号） |
| 待确认 | ① 报错文本的"客户号"到底指什么（client_id？invest_id？资金账号？）；② `invest_id` 与客户号的映射表/转换规则是否存在 |
| 影响 | 若映射不符，此查询返回空 → 仅作旁证，不影响主判定；确认后可将 `:client` 改为正确的绑定参数 |
| 确认人 | 结算资金模块负责人 |

## 2. tt_ftr_order.status 字典 010：'0' 是否表示"未成交"

| 项 | 内容 |
| --- | --- |
| 涉及 | `rb_self_trade.yaml` → step `reverse_pending`（主检查） |
| SQL | `SELECT ... FROM dimple.tt_ftr_order WHERE ... AND status = '0'` |
| 现状 | 代码注释已标注"status 为委托状态（字典 010），'0' 是否表示未成交需核对字典" |
| 待确认 | 字典 010 中委托状态码的完整取值：'0'='未成交/有效'？'1'='已成交'？'2'='已撤单'？是否还有 '3'='部分成交' 等 |
| 影响 | 若 '0' 不是"未成交"，反向委托主检查会漏报/误报自成交风险（这是 primary 检查，直接影响结论） |
| 确认人 | 报盘/委托链路负责人 |

## 3. tc_amout_limit_config.config_type 字典 334 的取值

| 项 | 内容 |
| --- | --- |
| 涉及 | `rb_position_limit.yaml` step `limit_config`（主检查）、`rb_pl_alert.yaml` step `pl_limit_cfg`（主检查）、`rb_net_position_alert.yaml` step `net_posi_limit`（主检查） |
| SQL | `SELECT ... config_type, alarm_value, limit_value, if_over ... FROM dimple.tc_amout_limit_config WHERE member_id=:member AND contract_id=:contract` |
| 现状 | 三张 runbook 共用此表，但未按 `config_type` 过滤：限仓 / 盈亏限额 / 净头寸限额可能是同一张表的不同 `config_type` 取值 |
| 待确认 | 字典 334 中：限仓（多空/净）对应哪个取值？盈亏限额对应哪个？净头寸对应哪个？`if_over`（字典 027）的语义是"超过即拦截"吗？ |
| 影响 | 未按类型过滤时，主检查可能命中错误类型的限额记录（如拿盈亏限额当限仓用）；建议确认后三条 SQL 各自加 `AND config_type='X'` |
| 确认人 | 风控参数配置负责人 |

## 4. tc_quote_risk_config.risk_type 字典 409 的取值

| 项 | 内容 |
| --- | --- |
| 涉及 | `rb_timeout_alert.yaml` step `timeout_cfg`、`rb_one_side_alert.yaml` step `one_side_threshold`、`rb_self_trade_alert.yaml` step `self_trade_threshold`（主检查） |
| SQL | `SELECT ... risk_type, numbers_limit, duration_limit, if_valid ... FROM dimple.tc_quote_risk_config WHERE ...` |
| 现状 | 三张 runbook 共用报价风控参数表，但未按 `risk_type` 过滤：超时 / 持续单边 / 自成交预警可能是不同 `risk_type` |
| 待确认 | 字典 409 中：超时类、持续单边类、自成交类分别对应哪个 `risk_type` 取值？`numbers_limit`（次数）与 `duration_limit`（时长秒）的适用口径 |
| 影响 | 未按类型过滤时，超时/单边/自成交可能互相命中错误参数；建议确认后各加 `AND risk_type='X'` |
| 确认人 | 报价风控负责人 |

## 确认后的落地动作

| 4 | 三个 runbook 对应 step 注释 | 加 `AND risk_type='X'` |

改完跑回归：`uv run pytest tests -q`（`tests/unit/test_runbook_integrity.py` 会兜底表/列一致性）。

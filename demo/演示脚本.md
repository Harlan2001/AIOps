# 领导汇报演示脚本（5 分钟主场 + 备用问答）

> 入口：仓库根执行 `uv run streamlit run demo/app.py`，浏览器 http://127.0.0.1:8501
> 开场前：① 提前 3 分钟启动并依次点开五个页签预热（ML 模型与案例索引首次加载约 2 秒）；
> ② 侧栏五个状态灯确认：ML/数据集绿灯、公网 LLM 绿灯、Oracle 红灯（预期，演示非必需）、
> 知识库黄灯（未挂载，正式部署挂载）。
> 定位话术：**这是规划中私有化内网 Web 工作台的快速 POC，内核零改动；
> 正式版是 FastAPI + Vue3 + MySQL。**

## 0:00–0:50　① 首页总览：先讲产品，再讲能力

- 一句话定位：清算系统 Oracle 业务报错的**已知报错根因诊断工作台**——
  输入一条报错，输出「问题是什么 + 怎么解决 + 可复核的证据链」。
- 指标卡带过规模：8.97 万条真实历史日志回归；**ML 在入口拦掉 94% 噪音/ORA，零 token**；
> 规则补齐 Top30 后真正调大模型的只有 **0.40%**；模型 1.7MB、纯 CPU、毫秒级。
- **重点（产品化规划）**：模块地图——蓝点 4 个是今天 POC 已落地的
  （诊断查询、诊断报告、统计看板、历史回看），灰点 5 个是 P1–P4 规划
  （事件中心、规则/知识管理、系统管理 RBAC、诊断 API、运行总览）；
  底部路线图从服务化 MVP 讲到私有化交付。

## 0:50–3:00　② 诊断查询：三个样例讲清三种命运（核心段落）

**样例①「噪音拦截」** → 点开始诊断：
- 五步路径灯：分流 ✅（noise 1.00），其余 ⏭️；蓝色徽标「ML 快速路径 ⚡零 token」。
- 话术：94% 的日志是"任务成功/无数据流水"，过去也淹没一线，现在**毫秒级直接分诊，不查库不花钱**。

**样例⑤「存续期变更失败」**（长尾，公网 LLM）：
- 路径：召回历史案例（可能只有个位数次数）→ 知识检索 → 规则未覆盖 ⏭️ → 升级 LLM；
- 紫色徽标；注意置信度约 0.3–0.4、红字**「证据不足，建议人工复核」**。
- 话术（诚实是卖点）：长尾问题模型不硬编结论，明确告诉一线"还需查什么"，
  处置步骤具体到菜单和表；这正是**人机协同**而不是替代专家。

**样例③「结算价不存在」**（高频已建规则；若内网不通会出黄条）：
- 内网在线时：绿色「规则快速路径 ⚡零 token」+ ③号折叠里是真实只读 SQL 行级证据，
  强调**系统真查了生产库，且全程只读**；
- 内网不通时（今晚预期）：黄条明示"现场查库已跳过"，结论仍基于真实 ML 分流/召回 + LLM；
  顺势说：**任何网络状况系统都不卡死、不假装，降级路径是产品级设计的一部分**；
  完整三证案例翻到「历史诊断」页的离线样例（见 3:40）。

可选样例：②ORA（转 DBA 话术）、④持仓不足（旗舰长文本，离线样例有完整版）、
⑥用户名密码错误。开关演示：勾选「强制走 LLM」可对高频问题强制三证推理。
> 不要现场用 TLOG ID 模式（依赖内网 Oracle；侧栏红灯时按钮自动停用）。

## 3:00–4:00　③ 统计看板：降本主线

- 两组对比卡：当前 3 类规则覆盖 271 条/0.30%，5,065 条要调 LLM；
  规则补齐 Top30 后 4,978 条走零 token 快路径，**LLM 调用降到 358 条/0.40%，降幅约 93%**。
- 点「现场实时重测」：**全程离线、不连库不耗 token**，约 1 分钟重放 8.97 万条，
  数字刷新与基线一致——说明这不是 PPT 数字，是可重复验证的回归基线。
- 若时间紧/怕等：跳过按钮，直接讲内置基线数字（话术："离线随时可复算"）。

## 4:00–4:40　④ 历史诊断：证明"真跑过"+ 离线兜底

- 上半：7 个真实案例的预跑 LLM 报告（含持仓不足的行级查库证据与 8 步处置），下拉切换；
- 下半：离线结构化样例（如 `493325942 库存不足`、`636445574 密码错误`）——
  **与实时诊断同一套渲染器**，断网也能展示完整结论卡；强调"预跑时间戳"标注，不冒充实时。

## 4:40–5:00　⑤ 架构页：合规与路线收尾

- 五层流水线一句话带过；五种来源表说明每条结论都**可审计**是谁产出的；
- 降级矩阵：全通/仅公网/仅内网/全断四列，主动说"明天哪怕断网，演示也完整"；
- 合规三句收尾：只读三重约束、知识库只读 SQL 默认不执行、
  开发期只连公网 LLM（仅报错文本，不含口令）、交付前切内网 vLLM 做到数据不出网。

## 备用问答

- **和直接用大模型比？** 94% 不调模型、毫秒零成本；调模型的 6% 也带三类证据，
  结论可复核、置信度可审计；模型换了结论还在（证据/规则不依赖具体模型）。
- **答错了怎么办？** 低置信明示人工复核；未覆盖类型走回流→补规则/重训的数据飞轮；
  全程只读不可能改坏数据。
- **数据安全？** 见架构页四条；知识库按客户投影交付，内部全集不外发。
- **落地节奏？** P1 服务化（FastAPI 已预留 extras、契约就是 diagnose()）；
  P2 正式工作台+事件中心；P3 闭环；P4 私有化规模化。

## 故障应急（断网/超时）

| 现象 | 处置 |
|---|---|
| 公网 LLM 超时/不通 | 结论自动变橙/灰「兜底」徽标，不报错；改讲降级设计与离线样例 |
| 内网 Oracle 不通（预期） | 黄条明示跳过查库；规则类证据翻历史批量报告与离线样例 |
| 全断网 | 只演：样例①②秒诊、统计看板（含重测）、历史报告、离线样例、架构页 |
| Streamlit 进程异常 | 终端 Ctrl+C 后 `uv run streamlit run demo/app.py` 重启（2 秒） |
